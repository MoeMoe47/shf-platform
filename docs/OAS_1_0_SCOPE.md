# OAS 1.0 scope

Repository scope and contract closure under the user task directive. FOUNDING GOVERNANCE is not external consensus. This is not an adopted standard or issued RC; real exact-snapshot founding acceptance is still missing.

Purpose: a universal provider-authored description and declaration baseline for an autonomous-system version in an explicit operating scope. The baseline makes identity/accountability, purpose/boundaries, available capabilities, used resources/dependencies, permissions/mechanisms, policy constraints, human authority, verification/monitoring plans and version/lifecycle/retirement information inspectable across platforms. It does not promise operational efficacy.

A declaration snapshot fixes the subject version, operating context and referenced manifests. Changes require a newly pinned declaration or withdrawal; a previous declaration is historical, not silently current. Dynamic sets may be described by a version-specific manifest/selector, not by sampled observed actions. Unknown completeness is explicit unknown, never satisfied.

Fourteen content-approved requirements cover all eight domains; no equal-count rule was used. Profiles are intentionally empty: no distinct system-class/environment/subset use case requires one. R0–R4 remains informative and does not create applicability thresholds. Deferred IDs 0011/0013/0015 retain reservations for operational control efficacy, escalation and evidence-model extensions. Their concepts are not deleted: constraints are disclosed by 0010, human responsibility/interfaces by 0012, and evidence linkage is defined by the declaration contract.

Non-goals: runtime safety guarantees, a universal legal blacklist, grants of system permission, proof of legal ownership, certification, trust scoring, Registry issuance/lifecycle, a marketplace or commercial obligations. The first release is not a complete execution-governance or sector-specific safety standard. Future releases may add those governed concepts with new immutable IDs/releases and explicit migration/supersession.

Compatibility: published public-review.1, its schemas and existing SHS reporting remain unchanged. Earlier authoring/review snapshots are retained as history. This closure is an explicit derived scope over the exact e1b6135 candidate records, not a second independently edited normative standard. Human requirement text is generated from that same source.
