# OGL-4 — Guidance Center + DGAL + Companion Integration

**Scope:** OGL-4 representative integration; system-wide rollout remains OGL-5.

## 1. Executive Result
The canonical Guidance Center is implemented as a bounded contextual shell mounted in the canonical Hub OGL runtime. It composes OGL-2 context, OGL-3 tour controls, checklist projection, DGAL status/references, contextual questions, safe actions, What’s Changed metadata, and a read-only Companion entry point.

## 4. Scope Boundaries
No OGL-5 rollout, authoring CMS, analytics dashboard, new migration, SEA work, or Accessibility project work was started.

## 5. Guidance Center Architecture
`src/system/guidance/GuidanceCenter.jsx` is the reusable shell. It is mounted by `CanonicalHubTour` and rendered through a portal without owning domain state.

## 6. Guidance Center vs DGAL Document Center
Guidance Center discovers and orchestrates contextual help. DGAL remains authoritative for document requirements, lifecycle, acknowledgment, signatures, and document state. OGL stores no document bodies.

## 7. Context Input
The shell consumes authenticated `/orientation/context` output and bounded `/orientation/experience` UX state. It does not resolve roles, permissions, organization, workflow, or requirements locally.

## 8. Output Model
The projection is organized as context, about, tour, next steps, documentation, common questions, Companion, and What’s Changed. Each displayed domain item retains its source/status boundary.

## 9. About This Area
The panel shows the selected orientation title and purpose from the OGL-2 projection.

## 10. Tour Integration
Take, resume, replay, and accessible-guide actions dispatch the existing `dgal:tour-request` contract to OGL-3. No second runtime is created.

## 11. Next Steps
Checklist entries are read-only OGL-2 projections, bounded to six visible items, and preserve source state and responsible party.

## 12. Responsibility / Waiting States
The resolver-provided responsibility and state labels are displayed; the shell does not infer who owns a waiting item.

## 13. Blocked States
Blocked status is preserved from the resolver. No remediation or completion claim is invented by the shell.

## 14. DGAL Documentation Integration
DGAL references and source status are rendered from the resolver’s documentation projection. `AVAILABLE`, `PARTIAL`, and `UNAVAILABLE` remain distinguishable.

## 15. Document Authorization
Only resolver-filtered references are eligible for display. Protected document authorization remains DGAL/server authoritative.

## 16. Safe Open / Return
Internal actions use structured route references and a bounded route mapper; arbitrary URLs and script schemes are rejected. Execution must reauthorize through the canonical route/service path.

## 17. Companion Integration
The shell opens the existing `CompanionProvider` through `useCompanion`. Suggested topics are derived from the OGL-2 projection and are bounded to five.

## 18. Companion Suggested Questions
Topics such as current work, pathway, evidence requirements, approved scope, and human approval are source-provided, not generated by the shell.

## 19. Companion Source Traceability
Companion remains the existing source-aware read-only surface. OGL passes no untrusted free-form workflow claims or privileged action URLs.

## 20. Common Questions
The Common questions section exposes only the deduplicated topics returned by OGL-1/OGL-2 context.

## 21. Related Workflows
Next-step safe route targets provide bounded related workflow openings. A missing or unauthorized target is omitted rather than guessed.

## 22. What’s Changed
The section reflects resolver reorientation metadata and distinguishes current orientation from a changed version. “Seen” is experience state, never acknowledgment.

## 23. First-Time Experience
The shell leads with About, the tour, and current next steps when no experience state exists.

## 24. Returning Experience
Started/paused experiences expose Resume; completed experiences expose Replay. Introductory interruption is reduced without hiding help.

## 25. Experienced User Behavior
The panel remains manually available and does not profile competency or nag users.

## 26. Accessibility
The shell uses dialog semantics, headings, explicit labels, keyboard-close behavior, focus entry/return, responsive layout, and the OGL-3 accessible step-list path.

## 27. Focus / Overlay Management
Opening focuses the panel; Escape/backdrop close restores the launch control. The launcher is positioned separately from the tour launcher to avoid pointer interception and overlay stacking.

## 28. Mobile / Responsive
At narrow widths the panel becomes a full-width sheet with scrollable content and preserved controls. OGL-3 acceptance covers 375px behavior.

## 29. Partial Source Failure
DGAL/context failure displays an unavailable/partial message and leaves the underlying workspace usable. It never renders an unavailable source as empty truth.

## 30. Error Isolation
The panel is optional presentation. Fetch failures are contained and do not mutate or gate the underlying workflow.

## 31. Deep Links / Notifications
The shell accepts only structured route targets from resolver output. Deep-link reauthorization remains the responsibility of the destination/runtime.

## 32. Context / Org Re-Resolution
The OGL-2 endpoint is called with the current destination/route and server-derived actor/org context. Org isolation remains server/API enforced; no client org switcher was added.

## 33. Telemetry Boundary
OGL-3 allowlisted experience events remain experience telemetry only. This phase adds no Evidence, Truth, or audit-authority writes.

## 34. Privacy
No document bodies, Companion free text, secrets, or sensitive workflow payloads are logged or persisted by the shell.

## 35. Representative Integrations
Hub Workspace is the browser-accepted representative. OGL-2 native/API tests retain Student, CivicSure, Agent Fabric, and role/org projections for later OGL-5 rollout.

## 36. Student / SHF Acceptance

## 37. CivicSure Acceptance

## 38. Hub / Admin Acceptance
Authenticated Hub browser acceptance passed: panel opens, sections render, close restores focus, and tour launch reaches the canonical runtime.

## 39. Agent Fabric / ARAG Acceptance
