→ Evidence
→ Authorized Review
→ Competency Decision

## 3. Proof Design Principle

Healthcare Workforce Readiness contains 60 proposed lessons.

It should not contain 60 competency proofs.

Most lessons are intended to:

- orient
- teach
- contextualize
- practice
- reflect
- assess understanding
- produce evidence candidates

Only a small number of activities should become formal proof activities.

A proof activity should exist only when:

- the learner capability is meaningful enough to verify
- the capability is appropriate for SHU readiness authority
- a reviewer can reasonably evaluate the evidence
- the activity does not simulate regulated authority misleadingly
- the evidence can be evaluated consistently
- functional equivalence with existing competency/proof infrastructure has been reviewed

## 5. Proof Classification Model

Each proposed proof is classified as one of:

### REUSE

An existing competency and proof configuration is functionally equivalent.

Healthcare supplies context only.

### CONTEXTUALIZE

The underlying competency/proof authority is reusable, but healthcare-specific prompts, scenario content, or evidence instructions are required.

### EXTEND

An existing competency family is close, but the current proof shape does not fully demonstrate the healthcare-readiness capability.

Extension may be justified after review.

### NEW CANDIDATE

No functionally equivalent competency/proof authority has been found.

A new competency/proof configuration may be proposed later, but only after canonical review.

No new competency ID may be invented in this document.

## 7. Healthcare Handoff — Target Capability

The learner should demonstrate the ability to communicate a structured workplace handoff that is:

- clear
- relevant
- concise
- accurate to the information provided
- respectful
- role-aware
- scope-aware
- explicit about uncertainty
- explicit about required follow-up
- appropriately escalated when necessary

This is a workplace-readiness communication capability.

It is not clinical judgment.

It is not a nursing handoff qualification.

It is not patient-care authorization.

## 9. Healthcare Handoff — Proposed Scenario Shape

The learner receives a synthetic healthcare-workplace scenario containing:

- assigned role
- current task or work context
- information that must be transferred
- known facts
- unresolved questions
- time-sensitive information
- role boundary
- escalation trigger
- receiving role

The learner prepares a handoff using an approved structured format.

The exact format may be textual, oral, or another accessible equivalent permitted by canonical policy.

The scenario must use synthetic information.

No real patient information is permitted.

- access production health records
- make independent patient-care decisions
- claim clinical authority

- identifies missing or uncertain information

- avoids inventing information

- confirms next-step responsibility appropriately

- material information omitted
- unsupported information invented
- uncertainty hidden
- escalation need ignored
- role boundary exceeded

## 18. Safety / Scope — Target Capability

The learner should demonstrate the ability to:

- recognize a potential workplace safety or scope issue
- distinguish known facts from assumptions
- recognize when they lack authorization
- stop rather than improvise outside scope
- identify an appropriate escalation path
- communicate the concern clearly
- document the decision appropriately
- avoid representing readiness as qualification

This is safety-awareness and professional-judgment readiness.

It is not clinical competence.

## 40. Functional Equivalence Gate

Before any new Healthcare competency or proof configuration is proposed, the implementation phase must answer:

1. Does an existing UCR competency already describe the learner capability?
2. Does an existing technical or cross-industry competency already describe it?
3. Can healthcare context be passed as scenario/configuration rather than authority?
4. Can an existing proof activity accept a healthcare-specific evidence prompt?
5. Would a new competency represent a genuinely different capability?
6. Would a new proof evaluate something materially different?
7. Who owns the capability canonically?
8. Who is authorized to review the resulting evidence?

If an existing capability is functionally equivalent, reuse is mandatory.
