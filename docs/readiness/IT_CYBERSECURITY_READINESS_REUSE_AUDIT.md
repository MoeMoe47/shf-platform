## Purpose

Determine what SHU already contains for IT & Cybersecurity Readiness before creating curriculum, services, registries, schemas, competencies, or authorities.

Required rule:

Audit → Identify Canonical Authority → Reuse → Extend → Consolidate Where Necessary → Build New Only When Proven Missing.

This branch must not create duplicate cybersecurity or networking authority.

## CONSOLIDATE

Any new IT & Cybersecurity course must consolidate with existing Data Center technical content where the learner capability is functionally equivalent.

Examples:

- Network troubleshooting should not become a second networking competency.

## SAFETY AND AUTHORIZATION BOUNDARY

Existing SHU cybersecurity content correctly uses defensive, synthetic, and authorized practice.

Preserve these boundaries.

Learners may:

- inspect synthetic data
- use approved disposable sandboxes
- interpret logs
- analyze access
- reason about identity and permissions
- troubleshoot simulated networks
- document incidents
- preserve evidence
- recommend authorized escalation

Learners must not be represented as authorized to:

- scan unauthorized systems
- exploit vulnerabilities
- bypass access controls
- crack passwords
- use stolen credentials
- deploy malware
- intercept traffic
- evade monitoring
- access production systems
- change real accounts without authority
- alter or destroy real evidence

Current architectural direction:

→ IT & Cybersecurity contextualization
→ reuse of existing technical-operations / networking / cybersecurity authorities

→ career connection
