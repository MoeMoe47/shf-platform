## 7. Defensive-Only Rule

All cybersecurity instruction must remain defensive, synthetic, and authorized.

Permitted learning patterns include:

- inspect synthetic records
- interpret synthetic logs
- analyze supplied alerts
- inspect approved disposable sandboxes
- reason about defensive configuration
- document evidence
- identify scope
- recommend escalation
- analyze simulated networks
- interpret supplied topology
- reason about user-support scenarios

## 8. Prohibited Activity Boundary

Learners must not be represented as authorized to:

- scan unauthorized systems
- exploit vulnerabilities
- crack passwords
- use stolen credentials
- deploy malware
- bypass access controls
- evade monitoring
- access production systems without explicit authorization
- intercept unauthorized traffic
- alter or destroy real evidence
- perform offensive operations against real targets

## 9. Classification Model

Each proposed lesson is classified conceptually as:

### TRANSFERABLE

Capability should primarily reuse Universal Career Readiness.

### CONTEXTUALIZED

Canonical capability exists but requires IT / cybersecurity examples.

### INDUSTRY-SPECIFIC

The lesson requires genuinely IT / cybersecurity-specific source instruction.

Final REUSE / CONTEXTUALIZE / EXTEND / MISSING decisions belong in Artifact 2.
