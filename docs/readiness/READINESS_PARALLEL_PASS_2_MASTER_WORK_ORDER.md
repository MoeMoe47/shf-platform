# Readiness Parallel Pass 2 — Master Work Order

Status: DRAFT — PASS 2 PLANNING
Baseline: `3d6f181`
Canonical branch: `agent/baseline-2026-10-06`

## 1. Purpose

Pass 2 converts the approved Pass 1 audits and blueprints into controlled source-curriculum plans and governed implementation work orders.

Pass 2 does not authorize uncontrolled lesson generation, duplicate competency authority, duplicate completion logic, new registries, or production publication.

The governing sequence remains:

Audit
→ Confirm Canonical Authority
→ Reuse
→ Contextualize
→ Extend Where Proven Necessary
→ Define Source Curriculum
→ Define Proof Activities
→ Validate Import Path
→ Build Draft Experience
→ Verify Governed Production Path

## 2. Pass 2 Scope

Each readiness domain must produce planning artifacts that define:

- source-curriculum structure
- lesson-level reuse map
- transferable versus industry-specific content
- competency reuse and gap analysis
- Prepare / Prove reuse and gap analysis
- evidence candidate design
- proof-activity design
- accessibility requirements
- safety and authorization boundaries
- Career mappings
- regulated-training boundaries where applicable
- import-validation strategy
- draft-experience strategy
- acceptance criteria

Pass 2 planning comes before implementation.

## 3. Canonical Authority Rule

No course may create a replacement authority for:

- curriculum
- competency definitions
- evidence
- verification
- competency decisions
- completion
- assignments
- learner progress
- credentials
- portfolio
- Career
- accessibility or accommodations
- reporting
- tenant or organization authority
- entitlement
- Metaverse evidence authority
- Arcade mastery
- Truth reporting

Existing SHU authorities remain controlling.

## 4. Reuse Hierarchy

Every lesson, activity, competency, proof, and system dependency must be evaluated in this order:

1. REFERENCE
2. CONFIGURE
3. COMPOSE
4. EXTEND
5. BUILD NEW ONLY WHEN PROVEN MISSING

A course may not create a new artifact merely because the wording, industry, or destination is different.

Functional equivalence controls.

## 5. Source Curriculum Rule

Source curriculum must be authored from the approved blueprint and reuse audit.

Before a new source lesson is written, the course must determine whether an existing lesson can be:

- reused unchanged
- reused with contextual framing
- reused with industry examples
- referenced as prerequisite material
- extended through a new activity
- extended through a new assessment
- extended through a new evidence candidate

A new lesson is permitted only when the learning objective is genuinely missing.

## 6. Lesson Classification

Every proposed lesson must be classified as one of:

### TRANSFERABLE

Broad workplace capability that should remain cross-industry.

Examples may include:

- reliability
- communication
- teamwork
- problem solving
- task management
- documentation
- ethical conduct
- accessibility
- evidence self-advocacy
- workplace financial awareness

Transferable concepts should preferentially reuse Universal Career Readiness.

### CONTEXTUALIZED

Existing capability taught through industry-specific examples without creating new competency authority.

Examples may include:

- safety escalation in healthcare
- reliability in construction
- communication during logistics handoffs
- documentation in biotech
- incident coordination in utilities

### INDUSTRY-SPECIFIC

Capability genuinely specific to the industry domain and not already governed elsewhere.

Industry-specific lessons require explicit evidence from the Pass 1 audit that the capability is missing.

## 7. Competency Rule

Do not fabricate competency IDs.

Every competency reference must be one of:

- existing canonical competency definition
- existing competency family without invented ID
- candidate competency pending canonical creation review

Before proposing a new competency definition, the course must document:

- what learner capability is missing
- why existing competency definitions are not functionally equivalent
- why contextualization is insufficient
- which authority should own it
- which proof activity would demonstrate it
- which reviewer role is authorized to decide it

No local competency registry is permitted.

## 8. Prepare / Prove Rule

Existing Prepare / Prove configurations must be reused where functionally equivalent.

Before defining a new proof configuration, document:

- missing competency capability
- existing proof configurations reviewed
- reason each is insufficient
- proposed evidence shape
- authorized reviewer
- pass / revise criteria
- safety boundary
- whether the proof is synthetic, simulated, classroom, supervised, or external

Proof submission alone does not establish verified competency.

## 9. Evidence Rule

The canonical evidence chain remains:

Activity Result
→ Evidence
→ Authorized Review
→ Competency Decision

AI, Arcade, Metaverse, simulation, and automated systems may create evidence candidates only unless an existing canonical policy explicitly authorizes more.

No course may directly write verified mastery from a simulation result.

## 10. Completion Rule

Use the canonical Completion Policy.

No course-specific completion engine is permitted.

Course completion remains distinct from:

- competency verification
- credential
- certification
- licensure
- apprenticeship status
- employment qualification
- employer authorization
- job placement

Arcade or Metaverse activity must not become automatically required unless canonical Completion Policy explicitly includes the governed activity.

## 11. Career Rule

Career mappings must use canonical Career authority.

Pass 2 may propose:

- pathway relationships
- career exploration
- role clusters
- transition plans
- employer-validation needs
- external training bridges

Pass 2 must not create unsupported claims about:

- salaries
- job placement
- credential eligibility
- licensure
- employment eligibility
- employer qualification

Static or fixture career data must be labeled as reference-only where appropriate.

## 12. Accessibility Rule

Every course must preserve canonical accessibility and accommodation systems.

Source curriculum planning must consider:

- readable structure
- keyboard access
- screen-reader compatibility
- captions or transcripts
- reduced motion
- color-independent communication
- alternative evidence methods where allowed
- learner accommodations
- plain-language support
- accessible simulations

Accessibility requirements must be designed into the lesson experience, not added afterward.

## 13. Safety Rule

Every domain must define:

- awareness boundary
- readiness boundary
- supervised training boundary
- external qualification boundary
- prohibited unsupervised actions

No readiness course may imply authorization to perform regulated, hazardous, professional, production, clinical, transportation, electrical, mechanical, financial, cybersecurity, or other controlled work.

## 14. Regulated Training Rule

Where an industry requires external regulated training, certification, licensure, apprenticeship, employer qualification, or clinical / technical authorization:

SHU readiness may prepare the learner for the pathway.

SHU readiness may not represent itself as the external authority unless that authority is separately established and governed.

## 15. Cross-Course Consolidation Rules

### Electrical

Construction and Energy must reuse Data Center electrical-infrastructure capability where functionally equivalent.

No duplicate electrical competency authority.

### Mechanical / HVAC

Construction must reuse existing mechanical/HVAC capability where functionally equivalent.

No duplicate HVAC competency authority.

### Networking / Cybersecurity

IT & Cybersecurity must reuse existing networking-fiber and cybersecurity-security capability where functionally equivalent.

No duplicate technical authority merely because the course is cross-industry.

### Logistics / Transportation

Logistics owns logistics-process learning such as:

- warehouse flow
- inventory
- receiving
- shipping
- freight documentation
- supply-chain coordination
- port logistics

Transportation owns mobility-context learning such as:

- commercial driving readiness
- fleet
- vehicle inspection awareness
- transit
- rail
- aviation
- roadway systems
- transportation incident coordination

Shared dispatch concepts must be mapped carefully rather than duplicated.

### Business / Financial Operations

Business may teach operational finance concepts but may not replace:

- Treasury
- Credit
- Debt
- banking authority
- accounting general ledger
- payment authority
- procurement authority
- Sales
- BOS

### Healthcare / Biotech

Healthcare owns healthcare-workforce and clinical-boundary context.

Biotech owns regulated manufacturing, GMP awareness, quality, documentation, cleanroom / controlled-environment, and production context.

Neither becomes regulated practice authority.

## 19. Lesson Reuse Map Requirements

Each lesson reuse map must identify:

- proposed lesson
- existing source reviewed
- reuse classification
- exact source path where known
- reason for reuse or non-reuse
- whether competency authority already exists
- whether proof configuration already exists
- whether new content is actually required

Classifications:

- KEEP — CANONICAL
- REUSE
- CONTEXTUALIZE
- EXTEND
- CONSOLIDATE
- REFERENCE ONLY
- MISSING

- verification boundary

- safety constraints
- simulation status
- whether existing Prepare / Prove configuration can be reused

Do not fabricate competency IDs.

- source curriculum must parse
- source curriculum must validate
- preview must succeed

- execute path must remain governed
- draft state must be preserved unless later approved

Not every lesson must use every optional experience element.

Arcade and Metaverse remain optional unless governed policy requires them.
