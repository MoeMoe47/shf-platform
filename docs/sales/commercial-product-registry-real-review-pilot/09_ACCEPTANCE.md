# 4H Acceptance

4H is accepted only when:

- canonical activation path is documented;
- no parallel Identity system exists;
- readiness checklist exists;
- controlled pilot candidates are bounded to 2-4;
- least-privilege gate matrix exists;
- dry-run works without mutation;
- activation requires explicit confirmation;
- wildcard candidate and gate are refused;
- expiry is required;
- self-provisioning is prevented;
- unauthorized operators are rejected;
- queue scope is verified;
- UI handoff is documented;
- real decisions are manual and governed by 4D/4F validation;
- revocation, expiry, and multi-org drills pass in disposable PostgreSQL;
- audit evidence exists;
- no fake human approvals are generated;
- no real credentials are stored;
- no production onboarding occurs;
- readiness, sellability, and lifecycle are not mutated;
- tests, typecheck, PostgreSQL acceptance, and `git diff --check` pass.
