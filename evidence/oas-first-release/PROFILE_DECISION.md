# First-release profile decision

No source-backed system-class, environment, sector or requirement-subset use case establishes a real OAS profile. The authoring set proposes a single description-record scope with explicit per-requirement applicability. R-levels are contextual risk guidance, not profiles; canonical domains are categories, not profiles. Registry display profiles and SHS package labels are not OAS profiles.

Decision for review: leave profiles empty for the first release. Both published catalog and review source keep empty arrays; review declarations require profile_reference null. This does not assert that all future systems share one risk model. OAS may later define profiles only with an evidenced use case, explicit requirement membership, adopted standard/release relationship and stable versioned identifiers. No profile population is needed to adopt a real first requirement set.
