# Declaration compatibility

The new 1.1.0 contract has standard/release pins, all included requirement references, separate applicability and provider assertion, declarant reference/time, evidence references/types, scope, notes and fixed NOT_EVALUATED. Validation requires an actual supplied matching release catalog, exact requirement coverage, no deferred/unknown IDs, resolved evidence references, reason for not-applicable and no satisfied assertion with unknown applicability.

Legacy declaration v1 remains supported unchanged for public-review.1 standard-level references. It is not automatically upgraded or interpreted as requirement-level conformance. New contract tests use clearly synthetic release metadata; no live RC is fabricated to validate declaration syntax. No production declaration is accepted against a nonexistent RC.
